# 작업 기록 작성 및 Git 추적 규칙

## 기록 구분

- `오늘 작업 끝`이라는 명시적 요청이 있으면 일일 마감 기록을 `daily`에 작성한다.
- 마지막 일지 이후의 작업이나 작업 중간 내용을 정리하는 요청은 `progress`에 기간별 진행 기록으로 작성한다. 일일 마감으로 간주하지 않는다.
- 사용자가 특정 문서의 보관 폴더나 이름을 명시하면 해당 지정을 우선한다. 마지막 일지 이후의 이번 기록은 `daily/5번째_작업_기록.md`로 보관하며, 다음 작업 기록은 6번째부터 이어 간다.
- 구현 완료, 설계 제안, 미검증 상태를 구분하고 관련 문서 목록을 갱신한다.

## 날짜 표기 금지

- 작업일지와 기간별 진행 기록의 파일명, 제목, 본문, 작업·검증 이력 표, README의 링크 문구에는 달력 날짜와 일자를 쓰지 않는다.
- `N번째_작업_기록.md`, `N번째_일지_이후_진행_기록.md`처럼 회차로 구분한다. 본문에서는 작업 순서·단계·커밋 해시로 이력을 설명한다.
- 성장에 걸리는 60초 같은 기능상 시간 값과 소스의 StartAt/EndAt 같은 식별자는 유지한다. 금지 대상은 기록을 구분하기 위한 달력 날짜다.
- 작성 후 파일명과 문서·목록에 날짜가 남지 않았는지 확인한 뒤 Git에 추가한다.

## 작성 후 자동 Git 추적

- 일일 작업일지와 기간별 진행 기록을 생성하거나 수정하면, 별도 요청 없이 해당 기록의 정확한 경로를 지정해 `git add -- <기록 경로>`를 실행한다. 추적 등록과 변경 내용의 스테이징까지가 기록 작성의 완료 조건이다.
- 기록과 함께 갱신한 README 등 문서 목록도 정확한 파일 경로를 지정하여 스테이징한다. 다른 작업과 섞인 변경이 있다면 이번 기록에 해당하는 변경만 추가한다.
- 파일이 속한 실제 Git 저장소에서 실행한다. 이 프로젝트의 게임 저장소는 작업공간 아래 `Project`이며, 작업공간 루트와 혼동하지 않는다.
- `git ls-files --error-unmatch -- <기록 경로>`와 경로를 제한한 `git status --short`로 추적 등록을 확인한다. 새 기록이 `??`로 남아 있으면 완료로 보고하지 않는다.
- ignore 규칙 때문에 추가되지 않으면 `git check-ignore -v`로 원인을 확인한다. 일지 Markdown에 한정해 필요한 예외 또는 명시적 강제 추가를 적용하며, 로그·추출 에셋·패키지 등 다른 파일의 제외 규칙을 일괄 해제하지 않는다.
- `git add .`, `git add -A`처럼 무관한 소스·에셋·사용자 변경까지 포함하는 명령은 사용하지 않는다. 기존 스테이징 내용을 되돌리거나 덮어쓰지 않는다.
- 자동 처리는 Git 추적·스테이징까지다. 커밋과 푸시는 별도 요청이 있을 때 수행한다.

## 적용 이력

- 기간별 진행 기록이 저장만 되고 미추적 상태로 남았던 문제를 확인했다. 일지 생성·수정 후 Git 추적 확인을 필수 절차로 추가하고, 해당 기록과 문서 목록에 적용했다.
- 날짜 제외 지침이 저장된 일지 규칙에서 누락되어 달력 날짜가 들어갔던 문제를 수정했다. 날짜 없는 회차 기반 파일명과 작업 순서 표기를 명시했다.
