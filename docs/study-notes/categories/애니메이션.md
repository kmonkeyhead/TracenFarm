# 애니메이션 질문

캐릭터 애니메이션, 표정 변화, 애니메이션 클립 재생과 루프에 관한 질문을 모은다.

## 표정 애니메이션

- **MINI 캐릭터의 표정은 몰프(BlendShape) 방식인가?**  
  MINI 얼굴은 일반적인 BlendShape 중심 구조와 다르며, 얼굴 파츠와 텍스처·UV 전환 구조를 함께 확인해야 한다. 자세한 내용은 [MINI 표정은 몰프인가](../MINI_표정은_몰프인가.md)를 참고한다.

- **눈 깜박임에 중간 과정이 없는 이유는 무엇인가?**  
  원본 데이터의 눈 상태 구성과 재생 방식을 함께 확인해야 한다. 자세한 내용은 [눈 깜박임에 중간 과정이 없었던 이유](../눈_깜박임_중간_과정.md)를 참고한다.

## 클립 재생과 루프

- **Idle 애니메이션이 반복될 때 마지막 프레임에서 튀는 이유는 무엇인가?**  
  클립의 시작·끝 포즈, 루프 설정, 루트 및 본 곡선의 연속성을 확인해야 한다. 자세한 내용은 [Idle 루프 마지막 프레임이 튀는 현상](../Idle_루프_마지막_프레임_분석.md)을 참고한다.

## 이동 애니메이션 상태

- **걷기와 Idle 전환은 현재 속도로 판단해야 하는가, `SetMoveFlag`에서 처리해야 하는가?**  
  입력 함수 호출 여부가 아니라 이동 로직이 최종적으로 계산한 실제 이동 상태를 Animator 파라미터로 전달한다. 현재는 `Speed` float 또는 `IsMoving` bool을 사용하고, 작은 오차로 상태가 흔들리지 않도록 임계값을 둔다. `SetMoveFlag`는 이동 의도를 저장할 수는 있지만 애니메이션을 직접 재생하는 책임까지 갖지 않는 편이 입력·이동·애니메이션의 결합을 줄인다.

- **이동 중 매 프레임 Animator의 Walk bool을 `true`로 설정해도 되는가?**  
  `Animator.SetBool`은 상태를 직접 다시 재생하는 호출이 아니라 Animator 파라미터 값을 설정하는 호출이므로 같은 값을 매 프레임 전달해도 애니메이션이 처음부터 재시작되지 않는다. 일반적인 사용 방식이며, 성능상 문제가 될 가능성도 작다. 수평 속도의 제곱 크기를 작은 임계값과 비교해 물리 오차로 Idle과 Walk가 흔들리는 것을 막고, 필요할 때만 호출하고 싶다면 마지막 bool을 캐시해 값이 변할 때만 전달할 수 있지만 필수 최적화는 아니다.
